# Сайт для дачи
Code for website for renting rural houses to relax outdoor

## Бэкапы и восстановление БД

### Когда делается бэкап

Сервис `backup` в `docker-compose.yml` запускается автоматически перед `migrate`
на каждом деплое (`backup → migrate → seed → app`) и сохраняет дамп в томе
`backup_data` (`/backups` внутри контейнера). Хранятся 10 последних дампов.

Это **не** расписание, а страховка перед необратимой миграцией. Отдельного
регулярного бэкапа по времени сейчас нет — см. открытый issue про вынос за пределы
VPS и ротацию.

### Проверить, что дамп вообще восстанавливается

Бэкап, который не удалось восстановить, — это не бэкап. Проверка читающая: она
поднимает временную базу, восстанавливает дамп, сверяет число таблиц и убирает
временную базу за собой. Продакшен не затрагивается.

```bash
just db-check pre-20261007T214132.sql.gz
```

Успех выглядит так:

```
verified restore_check_tmp: 61 tables, 2 users
✅ dump is restorable; scratch database dropped
```

### Восстановить поверх продакшена

```bash
just db-restore pre-20261007T214132.sql.gz
```

Рецепт останавливает `app`, восстанавливает дамп и поднимает `app` обратно.
Дамп снимается с флагом `--clean --if-exists`, поэтому существующие объекты
удаляются, а схема собирается заново, а не сливается со старой.

Восстановление требует явного подтверждения: скрипт откажется работать без
`--yes`, а также откажется на дампе меньше 1 КБ — такая «пустышка» означает, что
`pg_dump` упал, а не что база пустая.

### Что делать, если `db-check` падает

1. Посмотреть размер дампа: `ls -l /backups` в контейнере `backup`.
2. Запустить бэкап вручную и прочитать вывод:
   ```bash
   TAG=$(git rev-parse --short HEAD) docker compose run --rm backup
   ```
3. Если в выводе `server version mismatch` — версия образа `backup` в
   `docker-compose.yml` разошлась с версией сервера БД. Они должны совпадать;
   при апгрейде базы обновляйте строку `image:` у сервиса `backup` одновременно.

### Важное о версии образа

`pg_dump` отказывается работать с сервером новее себя, поэтому тег образа у
сервиса `backup` обязан совпадать с мажорной версией сервера БД. Прод работает на
Postgres 17.x, поэтому используется `postgres:17-alpine`.

### Чего бэкапы пока не покрывают

Дампы лежат на том же VPS, что и продакшен, поэтому от потери самой машины они не
спасают. Вынос на внешнее хранилище — открытая задача.
